# GPS 跑步距离

代码已接入 `wx.startLocationUpdateBackground` 和 `wx.onLocationChange`，不代表当前 AppID 已获接口权限。尚需完成后台配置并在真机验证。完成记录同步公里数和可选 `routeShape` 轮廓；`paoxiaSync` 已于 2026-10-21 更新，运行状态 Active；小程序只读 identity 调用已确认返回 `routeShapeVersion: 1`。

## 发布前配置

1. 在小程序管理后台「开发管理 → 接口设置」核对并开通 `startLocationUpdateBackground`、`onLocationChange`。平台限制主体及服务类目；按实际业务核对健康管理类目资格，以后台审核结果为准。未开通可能阻止提审，不可仅以模拟器成功判断可发布。
2. 在用户隐私保护指引中声明收集地理位置用于跑步距离统计和轮廓生成，并说明会同步不含经纬度的形状，包括用户主动跑步期间的小程序后台和锁屏场景。代码使用 `requirePrivacyAuthorize`（可用时），随后由后台定位接口申请用户授权。
3. `app.json` 已声明 `requiredBackgroundModes: ["location"]`、使用的隐私接口及 `scope.userLocation` 用途说明。用户需允许使用期间及离开小程序后定位，并允许系统层面的微信定位。
4. 如果权限被拒绝或接口不可用，计时继续，显示定位不可用和设置入口，跑后仍能手填距离。设置入口只能修改用户授权，不能代替开发者后台的接口开通。

## 行为与限制

- 开始跑步后申请定位；页面隐藏时保留监听，暂停、完成、卸载跑步页时移除监听并停止定位。恢复重新取起点，暂停期间及填写表单期间的移动不计入。
- WGS84 相邻位置采用球面距离累计。忽略无效坐标、精度大于 30 米的点、超过 10 米/秒的跳点；移动距离至少超过 5 米及报告精度才累计。这是消费级 GPS 估算，弯道、楼宇遮挡、缓慢移动及系统降频均可能引入误差。
- 两个有效位置相隔超过 30 秒时重新取起点，不连接缺失路段，并提示可能不完整。前台计时器也检查长时间无信号；后台无回调的中断在回到前台或新位置到达时检测。
- 累计米数随有效增量写入本机；经纬度只存内存，本机草稿缓存相对位移，完成记录仅上传归一化路线轮廓。进程被清理后无法补回期间距离，恢复时提示核对。
- Done 自动回填两位小数公里数。Continue 后只追加新增 GPS 距离，保留用户之前的手动修正；没有测得距离时保留空白。保存/放弃继续沿用既有草稿清理流程。
- 权限申请与停止串行处理：在授权弹窗未结束时点击暂停/Done，迟到的成功回调不能重新开始累计。

## 验证

本地命令：`node scripts/check-location.cjs`、`node scripts/check-ui.cjs`、`node scripts/check-sync.cjs`。自动检查使用模拟位置与生命周期，不能证明真机后台服务持续可用。

真机待验收（iOS / Android）：

1. 同意隐私与前后台定位，室外等待 GPS 就绪，沿已知约 500 米路线行走/跑步，核对公里数与误差。
2. 静止 1 分钟观察漂移；暂停后移动，再继续，确认暂停期间移动不计入。
3. 分别锁屏、切回微信聊天及切换其他 App 运行 2–5 分钟；回来确认距离增加且无跨缺失路段突跳。
4. Done 后确认系统定位停止，草稿自动填距离；手动改距离，再 Continue 跑一段，核对只追加新距离。
5. 拒绝授权、关闭系统定位、弱信号、授权中点暂停或 Done，确认可继续计时与保存，提示明确且不重启已经结束的定位。
6. 跑步中清理进程再打开，确认已记录公里数仍在、显示距离可能不完整；完成、保存、放弃后不再定位。
7. 用中英文、小屏与大屏分别检查时间、距离、按钮均可见，现有历史的公里数与配速正常。

## 跑过的形状

- 只使用通过距离质量过滤的点，形成多段折线；首个点只建起点，定位漂移不进入轮廓。暂停、恢复、弱信号中断分段，不用直线补齐缺失路段。
- 本机未完成跑步和草稿保存相对起点的平面位移，不保存地理原点；地理原点仅存内存。Done 后 Continue 或进程重启时，新段从旧段末端附近重新定位，段与段之间的实际地理位置无法重建；这是大致形状而非可导航路线。
- 保存记录时统一居中、等比例缩放至单位正方形，坐标保留三位小数。云端 `routeShape` 只有 `version`、`partial` 和 `segments`，不含经纬度、地理原点、地址或每个点的时间。形状仍可能反映熟悉的路线轮廓，不等于严格匿名化。
- 最多 32 段、512 点；长路线渐进抽稀，保留各段端点。超过段数限制时保留已收集形状并标记不完整，距离统计继续。
- Day 详情使用柔黑线条展示；无轨迹的历史记录不显示空图，也不根据手填距离虚构路线。Year/Month 不传输轮廓点到视图层。
- 老版云函数不支持新字段时，客户端保留本机待同步记录并提示同步未完成，避免旧服务静默删除轮廓。
- 额外检查：`node scripts/check-route.cjs`；同步检查覆盖轮廓跨设备、旧服务保护和非法坐标拒绝。真机还需验证圆形、直线、折返路线，以及暂停/锁屏后的形状与断点。
